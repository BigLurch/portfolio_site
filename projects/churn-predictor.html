The project

I built this project to practise delivering a machine learning model as a usable application. The system uses synthetic telecom customer data and brings together feature engineering, model training, experiment tracking and API serving.

What I built

  • Reusable feature engineering and a scikit-learn preprocessing and model pipeline.
  • Logistic Regression training with evaluation metrics and MLflow experiment tracking.
  • FastAPI endpoints for individual and batch predictions, health checks and metrics.
  • A custom HTML, CSS and JavaScript interface with filtering, CSV export and what-if editing.
  • Docker packaging, Ruff and pytest checks in GitHub Actions, plus retraining and drift-check scripts.

Engineering decisions

Keep training and inference aligned

Reusable feature transformations and a saved preprocessing/model pipeline help keep the input processing consistent between training and prediction.

Build an interface around the API

The browser interface adds batch workflows, filters and editable customer rows so the demo can be explored without writing API requests.

Make the workflow repeatable

Containerization, automated checks and separate training scripts make the different stages easier to run and inspect.

Scope & limitations

This is a learning project built on synthetic data. Its evaluation results do not establish performance on real customers. Drift checks are script-based; model promotion and automated retraining orchestration remain areas for further development.

Where I'd take it next

A model registry promotion flow, real-data validation and a dedicated monitoring dashboard would be useful next steps.
